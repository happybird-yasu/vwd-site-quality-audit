# vwd-site-quality-audit

app-navi.biz の公開記事について、AdSense「有用性の低いコンテンツ」対応のための**読み取り専用**品質監査ツール。パイロット(20〜30ページ)での検証を経て、全件クロール(`post-sitemap.xml`の全URL、2026年10月時点で635件)にも対応。

## スコープと安全性

- **読み取り専用。** `GET` リクエストのみ。WordPress管理画面・Xserverサーバーパネル・記事の公開状態には一切触れない。
- 対象記事は、`post-sitemap.xml`(WordPress標準のサイトマップ)から取得した実在する公開記事URLに限定。推測でURLを組み立てない。**REST APIは使用しない**(サイト側でセキュリティ対策として匿名REST APIが無効化されているため。この監査ツール側でREST APIを再有効化するような変更は一切行わない)。
- `robots.txt` の `Disallow` を尊重する。
- 失敗時のリトライは最大2回まで(無限リトライなし)。失敗は `failures.jsonl` に記録して処理を継続。
- リクエスト間に1.5秒の間隔を空け、サイトへの負荷を抑える。
- 現在は `workflow_dispatch`(手動トリガー)のみ。無人夜間実行(スケジュール実行)は、パイロット結果を確認してから別途追加する。

## 実行方法

- パイロット(20〜30ページ、全テーマ+ホームページを均等サンプリング):GitHubの「Actions」タブ → `Pilot content quality audit (app-navi.biz)` → `Run workflow`。
- 全件(`post-sitemap.xml`の全URL+ホームページ):同タブ → `Full content quality audit (app-navi.biz)` → `Run workflow`。所要時間は概ね20分前後(635ページ×約1.8秒/件、1.5秒間隔込み)。

完了後、Artifacts(パイロットは`audit-report`、全件は`full-audit-report`)をダウンロードすると以下が入っている。

- `report.md` — 人間向けサマリー(全サンプルの一覧表、構造化データの問題、類似度が高い/固有テキストが少ないページの一覧)
- `report.json` — 機械可読な詳細データ
- `sample.json` — 今回選ばれたサンプルページの一覧
- `failures.jsonl` — 取得失敗したURLとその理由
- `estimated_load.md` — 全件クロールに拡大した場合の推定所要時間・リクエスト数
- `magi_classification.md` / `.json` — A/B/C/D一次分類(下記参照)
- `magi_review_queue.csv` — C/D判定ページのみ、優先度(High→Medium→Low)順に並べたレビュー用CSV(ChatGPT/Claudeでの後続レビュー向け)

## 役割分担(AdSense再審査対応)

- **GitHub(このリポジトリ)**: 客観データの計測とA〜D候補抽出のみ。最終判断は行わない。
- **ChatGPT**: ページ単体の利用価値・地域固有性の確認。
- **Claude**: 大量テンプレ感・サイト全体構造の確認。
- **人間**: 最終判断(公開継続/修正/下書き化)。

## MAGI一次分類(A/B/C/D)

`report.json` を元に `audit/classify_magi.py` が同じワークフロー内で自動実行される。**これは最終判定ではなく、数値上の精査優先度。** C/D判定は「人力/ChatGPT/Claudeで優先的に確認すべき」という意味で、即・下書き化や公開停止を意味しない。

各記事を以下の3軸でスコアリングする(100点正規化、A≧75 / B≧60 / C≧40 / D<40)。

- テーマ内類似率(30点)
- 固有文比率(25点)
- 同一言語内の全国版との類似率(20点)

**地域固有性(本来25点分)はここでは自動判定していない。** `report.json` には比較に使った後の本文テキストが残っておらず、「地域固有の観察が書かれているか」はテキスト内容を読まないと判断できないため。すべてのページに `region_specificity_pending: true` が付き、C/D判定のページは地域固有性を人力/ChatGPTで確認してから判断すること。

**多言語ページは減点理由にしない。** `run_audit.py` の類似率比較(テーマ内・全国版とも)は同一言語内のみで行う(例: 英語関東版 vs 英語近畿版は比較対象、日本語関東版 vs 英語関東版は対象外)。日本語原本と英語/独語/スペイン語/フランス語版が同一内容であること自体は問題にしない。同一言語の全国版が存在しない場合、全国版との類似率は `not_available` として無理にスコアを作らない。

**評価軸数(axes_scored)。** 各ページが3軸中何軸でスコアリングされたかを `2/3` のように表示する。全国版比較が `not_applicable`(そのページ自身が全国版)・`not_available`(同一言語の全国版が存在しない)・時間予算超過でスキップのいずれかの場合、その軸を除いた軸だけで100点に正規化するため、2軸のページと3軸のページを同じ信頼度として扱わない。

**要精査候補の優先度(High/Medium/Low)。** C/D判定ページのみに付与する。

- High: テーマ内類似率90%以上、または固有文比率15%未満
- Medium: テーマ内類似率80〜89%、または固有文比率15〜24%
- Low: それ以外だがC/D判定(主に全国版との差が原因など)

感染症・人口流動・道路交通量のテーマは `priority_review` フラグ付きで別表(Priority review themes)にまとめる。**ただし感染症週報(`infection`)は時系列データ更新型のため、本文類似率が高いこと自体を危険判定の根拠にしない**(`magi_classification.md` に注記あり)。

ワークフローのログにも、A/B/C/D件数・C/D合計・High/Medium/Low件数・テーマ別C/D上位10件を標準出力する(Artifactを開かなくても概要が分かるように)。

## 計測項目(第1段階)

- URL生存(HTTPステータス)
- 本文文字数
- 同一テーマ内の本文類似率(`difflib` によるペア比較)
- 全国版と地域版の類似率
- ページ固有テキスト量(推定)
- 内部リンク数・外部(出典候補)リンク数(本文内のみ、およびナビゲーション込みのページ全体、の2系統で計測)
- Dataset構造化データ(JSON-LD)の有無・`description`/`license`の有無
